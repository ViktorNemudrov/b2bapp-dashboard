# B2BAPP Dashboard — инструкции для Claude Code

## Разделение труда по дашборду (ВАЖНО — читать первым)

Данные дашборда (`public/data/data.json`) считает **только** детерминированный
скрипт `build_dashboard.py`. Логика сборки живёт в нём, больше нигде.
Фронт (html/js в `public/`) — **только рисует** уже посчитанные данные и
**ничего не досчитывает** (никаких вычислений загрузки, скоупа, критпути в
рендере — если такое встретилось, это баг, вынести в билдер).

### Маршрутизация просьб Виктора

Когда Виктор просит что-то про дашборд, определи тип и действуй так:

| Тип просьбы | Примеры | Кто делает |
|---|---|---|
| **Визуал / отображение** | «добавь фильтр по роли», «покажи задачи иначе», «другой цвет по статусу», «новая вкладка», «поправь вёрстку/график» | **Ты (Claude Code)** — правь фронт в `public/`. Данные не трогай. |
| **Логика расчёта** | «измени, как считается критпуть / загрузка / отсечка MVP / даты бэклога», «почему гант так посчитал», «поменяй правило вакансий/календарь» | **НЕ делай сам.** Ответь Виктору: «Это логика билдера — к Claude в сессию, он правит `build_dashboard.py`. Я применю новую версию скрипта, когда он её пришлёт.» |
| **Данные / обновление** | «обнови гант», «пересобери дашборд», «свежие цифры» | Нужно **сырьё от Claude в сессии** (`jira_dump.json`, `team_dump.json`). Без свежих дампов не пересобирай — данные протухнут молча. Запусти билдер (ниже). |

Правило одной фразой: **как ПОКАЗАТЬ — ты; как ПОСЧИТАТЬ и на ЧЁМ — Claude в сессии.**
Если сомневаешься, логика это или визуал — считай, что логика, и отправь к Claude.

### Как запускать билдер (режим gantt)

Виктор кладёт присланные Claude файлы (`jira_dump.json`, `team_dump.json`,
`build_dashboard.py`, если версия обновилась) в корень репо. Далее:

```bash
git fetch origin
git log --oneline -1 && git log --oneline -1 origin/main   # не разошлись ли
# при расхождении: git stash push -u; git reset --hard origin/main; git stash pop

python build_dashboard.py --mode gantt \
    --jira jira_dump.json --team team_dump.json \
    --data public/data/data.json \
    --out  public/data/data.json

# билдер сам валидирует и падает на ассерте, если данные битые.
# дополнительно быстрый парс-чек:
python -c "import json;json.load(open('public/data/data.json',encoding='utf-8'))"

git add public/data/data.json
git commit -m "data: gantt refresh ДД.ММ.ГГГГ"
git push origin main
# подождать ~30 сек, проверить https://b2bapp-dashboard.vercel.app/
```

Билдер **мёржит**: заменяет только gantt-секции, ветки `usm`/реестры из старого
`data.json` остаются нетронутыми. Частичное обновление — штатно.

### Грабли репо

- Ветка `main`, remote `origin`, автодеплой Vercel из `main`.
- Перед коммитом всегда `git fetch` + сверка с `origin/main` — Виктор мог
  пушить с другой машины. Расхождение — `reset --hard origin/main`, затем
  заново применить присланные файлы (не терять их).
- Битый JSON роняет ВСЕ страницы дашборда, не только изменённую — парс-чек
  обязателен до пуша.
- `manual.json` мёртв (решение 13.07.2026) — не создавать, не читать.
- `update.py` (GitHub Contents API + токен в `.env`) — устаревший, не
  использовавшийся механизм деплоя в обход git. Не запускать: он публикует
  файлы напрямую через API и может разойтись с состоянием `main`. Деплой —
  только через обычный `git commit` + `git push`, как описано выше.
